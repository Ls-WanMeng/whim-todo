# 05. 数据能力与隐私

> 返回导航：[../PLAN.md](../PLAN.md) | 调研依据：[00-竞品调研.md](00-竞品调研.md)
>
> **价值**：高 · **成本**：M–L · **优先级**：中期（v1.5）

## 一、为什么做

调研中「本地优先 / 隐私」成为显著差异化：Memos（自托管、零遥测、Markdown 存储）、Everdo（离线优先 + 加密同步）、Obsidian（本地 Markdown）都在强调数据自主。Whim Todo 已有 `file://` 双击打开 + JSON 导入导出，但缺少**多设备 / 跨浏览器的数据迁移**和**自动备份**，是「换设备 / 换浏览器」时的最大痛点。

## 二、拟做功能

### 1. 本地文件同步（File System Access API）
- 用浏览器 File System Access API，把数据自动写入用户指定的本地文件（如 `whim-todo.json`）。
- 用户换设备时，打开该文件即可恢复。
- 优点：完全本地、无服务器、隐私无忧；缺点：需用户手动指定文件、Chromium 系支持较好。

### 2. WebDAV 同步（可选，自托管用户）
- 支持 WebDAV 协议，把数据同步到自托管服务器（如群晖、Nextcloud）。
- 参考 Memos 的自托管定位，但成本高（需处理冲突、认证），放后期。

### 3. 自动备份 + 版本历史
- 定期把 localStorage 数据备份到 `whim-todo:backup`（或导出文件）。
- 保留最近 N 个版本的快照，误操作可回滚（呼应 A1 撤销的延伸）。
- 目前已有 `whim-todo:corrupt-backup`（损坏备份），扩展为「版本历史」。

### 4. 加密导出（可选）
- 导出 JSON 时可选 AES 加密（密码保护），保护隐私。
- 需引入加密库（或 Web Crypto API，原生可用）。

## 三、技术方案

- **纯函数层**：`src/lib/sync.ts`（文件同步的数据准备 / 校验）、`src/lib/backup.ts`（版本快照管理）。
- **Web Crypto API**：加密用浏览器原生 `crypto.subtle`，零新增依赖。
- **File System Access**：`window.showSaveFilePicker` / `showOpenFilePicker`，原生 API，注意浏览器兼容降级（不支持时退回手动下载/上传）。

## 四、验收标准

- 本地文件同步：保存后修改数据，文件内容实时/按需更新；换设备打开文件能恢复。
- 版本历史：误删后可回滚到最近快照。
- 加密导出：密码错误无法解密，密码正确完整恢复。
- 不破坏 `file://` 双击打开；不支持 File System Access 的浏览器有降级方案。

## 五、定位约束

- **坚持 local-first**：所有同步/备份默认本地，不强制云端、不强制账号。
- **零遥测**：不收集使用数据。
- **明确不做**：云账号、跨用户协作（延续「明确不做」清单）。
