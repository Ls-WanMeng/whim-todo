# 02. AI 自然语言增强

> 返回导航：[../PLAN.md](../PLAN.md) | 调研依据：[00-竞品调研.md](00-竞品调研.md)
>
> **价值**：高 · **成本**：M–L · **优先级**：长期（需代理层，方向性探索）

## 一、为什么做（以及为什么暂缓）

2026 年最大趋势是 AI 进入待办工具：Todoist `Assist`（拆解目标为步骤 + 智能排期）、TickTick `AI Task Analysis`（一句话拆子任务）、Notion AI（从笔记生成任务）、Motion（全自动排程）。但 **Whim Todo 定位 local-first、无需账号、零遥测**，而 AI 能力通常依赖代理层（服务端调用 LLM），与「数据只存本地」「不贩卖隐私」的定位存在张力。

因此本主题**标记为「方向性探索，暂不排期」**，仅在以下条件满足时启动：用户明确需要、且能提供本地/私有化的 AI 代理方案（如接入本地 Ollama、或用户自备 API Key）。

## 二、拟做功能（条件满足时）

### 1. 智能任务拆解
- 输入「准备季度汇报」→ AI 拆成「收集数据 / 写提纲 / 做 PPT / 排练」等子任务。
- 参考 TickTick `AI Task Analysis`；纯函数层可先做「模板拆解」兜底（无 AI 时用预设模板）。

### 2. 智能排期建议
- 基于任务优先级、历史完成时间、当前待办量，建议每个任务的 `dueAt`。
- 参考 Todoist `Smart Schedule` / Things 3 `When`。可先用规则引擎（优先级 + 空闲日）实现，无需 LLM。

### 3. AI 周报摘要
- 现有 `weeklyExport.ts` 只做统计（完成数 / 逾期数 / 标签），可升级为「自然语言周报」：AI 总结本周亮点、待改进点、下周建议。
- 参考 SelfManager 的 AI 周/月回顾。

## 三、可「无 AI 先做」的部分

即使不接 LLM，以下能力可以先用**规则/模板引擎**实现，未来再替换成 AI：

| 能力 | 无 AI 方案 | 有 AI 升级 |
|---|---|---|
| 任务拆解 | 预设模板（如「季度汇报 → 4 步」） | LLM 动态拆解 |
| 排期建议 | 规则引擎（优先级 + 空闲日 + 历史规律） | LLM 综合上下文建议 |
| 周报摘要 | 现有统计 + 固定文案模板 | LLM 生成自然语言 |

## 四、技术与定位约束

- **不破坏 local-first**：AI 调用必须是「可选、可关闭、显式授权」，默认全关闭。
- **隐私**：不默认上传数据；若接 API，需在设置面板明确说明「哪些数据会发送给 AI 服务」。
- **零遥测**：AI 功能不引入埋点。
- 需评估包体：接 LLM 需引入请求层，可能与「零新增依赖」冲突，须在 PR 中说明。

## 五、验收标准

- AI 功能默认关闭，开启需显式授权，关闭后产品行为与现在完全一致。
- 无 AI 时，「模板拆解」「规则排期」仍可用。
- 文档写明数据流向与隐私边界。
